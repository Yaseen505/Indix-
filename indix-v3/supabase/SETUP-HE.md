# חיבור INDIX לענן (Supabase): מדריך הקמה

תהליך חד-פעמי של כ-10 דקות.

## 1. יצירת פרויקט
supabase.com ← New project ← Name: `indix` ← Region: **Frankfurt** ← Create.

## 2. הרצת קובץ ההקמה
בתפריט הצד: **SQL Editor** ← New query. מדביקים את כל התוכן של `supabase/setup.sql` ← **Run**.
אמורה להופיע ההודעה "Success. No rows returned".

## 3. הגדרות כניסה
**Authentication ← URL Configuration:**
- Site URL: כתובת האתר ב-Netlify (למשל `https://chipper-macaron-f3ca0e.netlify.app`)

**Authentication ← Sign In / Providers ← Email:**
- Enable Email: מופעל
- Confirm email: מומלץ להשאיר מופעל. אפשר לכבות אם רוצים שעובדים ייכנסו מיד בלי לאשר מייל.

## 4. הדבקת המפתחות
**Project Settings ← API** (או Data API). מעתיקים:
- Project URL
- anon public key

ופותחים את הקובץ `config.js`:
```js
window.INDIX_CONFIG = {
  supabaseUrl: "https://xxxx.supabase.co",
  supabaseAnonKey: "eyJ..."
};
```
המפתח anon ציבורי מטבעו. ההגנה על הנתונים נעשית בהרשאות השורה (RLS) שהוגדרו בשלב 2.
**אסור להכניס כאן את ה-service_role key.**

## 5. העלאה ל-Netlify והקמה ראשונה
1. מעלים את התיקייה ל-Netlify.
2. המנכ״ל נכנס לאתר ← "עובד חדש? הרשמה" ← מייל וסיסמה ← מאשר את המייל ← נכנס.
3. מופיע מסך "הקמת המערכת בענן": בוחרים מערכת ריקה (לעבודה אמיתית) או נתוני דוגמה.

## 6. הוספת עובדים
1. המנכ״ל: ניהול והרשאות ← עריכת משתמש (או "+ משתמש") ← ממלא את **מייל הכניסה** של העובד, התפקיד והפרויקטים.
2. העובד: נכנס לאתר ← "עובד חדש? הרשמה" עם **אותו מייל** ← בוחר סיסמה ← נכנס, ורואה רק את מה שמותר לתפקיד שלו.

השבתת עובד חוסמת אותו גם בשרת, לא רק במסך.

## מה מוגן בשרת
- מי שהמייל שלו לא רשום ופעיל ב-INDIX לא יכול לקרוא או לכתוב שום נתון.
- רק מנכ״ל יכול לשנות משתמשים ותפקידים. ניסיון של עובד "לקדם את עצמו" נדחה בשרת.
- תמונות ומסמכים נשמרים ב-Storage בכתובת אקראית שאי אפשר לנחש.
